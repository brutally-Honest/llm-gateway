# 016: the session page (T016)

Covers what the automated tests cannot see for `specs/016-web-ui-v2`: the page in a real
browser against one session seeded with every case of the mockup
(`specs/016-web-ui-v2/mockups/v4-story.html`): layout and scroll, the overview and "Needs a
look", the turn list, each turn against the seed's printed lines, the four tabs, the details
dialog, live updates, keys, both themes with measured contrast, and `gateway timeline`.
The automated parts are `internal/timeline/view_test.go`, `internal/ui/api_view_test.go`,
`internal/ui/webtest/view.test.js`, `contrast.test.js` and `web_test.go`. Run steps 3–23 with
the `ui-check` skill; record expected against seen, and the contrast figures, in
`specs/016-web-ui-v2/research.md`.

## Setup

1. From the repo root, build and start a **throwaway** gateway on a fresh data folder and
   its own ports, forwarding model calls to the seed's stub upstream (`<cfg>` is a copy of
   your config file; nothing reaches a provider):

   ```sh
   make build
   GATEWAY_LISTEN_ADDR=127.0.0.1:17197 GATEWAY_UI_LISTEN_ADDR=127.0.0.1:17199 \
   GATEWAY_CAPTURE_DIR=/tmp/fx016-data \
   GATEWAY_EFFECTS_NETWORK_HTTP_PROXY_ADDR=127.0.0.1:17198 \
   GATEWAY_EFFECTS_NETWORK_SOCKS_PROXY_ADDR=127.0.0.1:17195 \
   GATEWAY_UPSTREAMS_ANTHROPIC_BASE_URL=http://127.0.0.1:17196 \
   bin/gateway -config <cfg>                     # in the background; leave it running
   ```

2. Seed one session (needs `git` and node 22.12+; the harness step wants the internet but
   is labelled harness without it):

   ```sh
   node docs/manual-checks/seed-session.mjs --fast --gateway http://127.0.0.1:17197 \
     --ui http://127.0.0.1:17199 --http-proxy 127.0.0.1:17198 --stub-port 17196
   ```

   It prints the session link, an `expected:` block with one line per turn, block and side
   call, and the CLI command. Keep that output beside the browser. Remove the scratch repo
   under `~/llmgw-seed-session/` when done. For step 18 run it a second time with `--live`
   added (a new session); stop it with Ctrl-C after step 18.

## Steps

### Layout (AC3)
3. Open the link in a window at least 1,400 px wide. Three columns: the turn list on the
   left, the story in the middle, the Files/Commands/Sites/Context card on the right. Only
   the story scrolls; the two side cards stay put. At about 1,000 px the page falls back to
   one scrolling page with the turn list sticky on the left.

### Overview (AC2)
4. The title is the seed's `title` line (generated by a side call), never the session key.
   Under it: status, time range, folder (full path on hover), model and client.
5. Five labelled cards: Time (model · tools · waiting · between turns, summing to the
   total), Files changed (lines `+a −r` and files read), Commands (the longest one), Sites,
   Context. Each card except Time opens its
   tab on the right.
6. "Needs a look" lists the failed Edit, the errored call (500), the change between turns 7
   and 8, the effects not pinned to one tool, the hooks-only turn 8 and the unmatched
   command. Each item opens its details or scrolls to its place and highlights it.
7. The token line shows input, output, cache write, cache read. "N side calls" is quiet
   (not red), opens to list the quota probe (429) and the title call; neither is a turn or
   an error anywhere on the page.

### Turn list (AC3)
8. One entry per turn (prompt clamped to two lines, full text on hover and on focus, its
   duration or "hooks only", files changed, failures) plus one entry for the between-turn
   block. Clicking an entry scrolls the story to it and marks it. Scrolling the story by
   hand moves the mark. Click the last turn (8): it is marked even though it cannot reach
   the top.

### The story (AC4–AC8)
9. For each `turn N` line the seed printed, the turn shows exactly that: heading = prompt
   (reminder behind "+1 reminder", which toggles), start time, clock time with
   model · tools · waiting, the pills, then one step per model call (`#n`, what it did and
   for how long, "then ran N at once:"). An errored call says its status as a word in red.
   Thinking never shows inline: "Read the thinking" is a link.
10. Tool lines: `✓` alone for ok, glyph and word otherwise; name, summary (`npm test`,
    `src/app.js +1 −1`, `pdf`), run time (`≈` when approximate), a failed call's first
    error line under it. Turn 7's Agent line holds its sub-agent block with its own steps
    and tools; the Agent's span is not counted as tool time.
11. Effect lines sit under their tool: label as glyph and word first (`● named`, `◐ only
    one running`), then what, the path relative to the folder (full path on hover), lines
    or size, and a Diff or View button. Turn 5's `◌ Not pinned to one tool call` group comes
    after both commands and names each by tool and first words. Turn 7's
    `○ Not caused by a tool call` group holds the harness connection with "during #n Bash".
12. The between block after turn 7 reads "Seen between turns 7 and 8", holds
    `notes/review.md` with `○ outside any tool call`, and appears in neither turn. Turn 8
    says "No model calls captured. The hooks saw:" and its command has no `#n`.
13. Every `#n` opens the 013 call drawer for that call; Esc closes it.

### Tabs (AC9, AC10)
14. Files: changed files grouped by path with lines and who changed them in words, then
    "Read" and "Searched" apart (Grep is a search, not a read). Commands: every shell
    command in run order with state, time and what it changed; turn 8's says "seen by hooks
    only". Sites: one row per host with connections, bytes and who; the footer names the
    unassigned connection and links to `#/effects/unassigned`. Context: Now / First call /
    Grew by, bars by turn (heights in proportion, each a link to its call), the main
    thread's rows with what each call added, and the sub-agent's rows apart.
15. The tabs are a tablist: Tab reaches the selected tab, Left/Right/Home/End move between
    tabs, the counts match the overview cards.

### Details dialog (AC11)
16. Open a file row, a command, a tool name in the story and a site. One dialog shape each
    time: kicker, title, labelled facts, why the effect is attributed in words, the diff or
    content (or output and input, with Copy buttons) in full width, the hook lines with
    state, reason and outcome, the hook input when it differs. Follow a related link inside
    the dialog, then Back returns. "Show in turn N" closes the dialog, scrolls to the row
    and highlights it. Esc closes and returns focus to what opened it.

### Live (AC12)
17. With the `--live` session open, scrolled to the bottom: each new turn appears without a
    reload and the story follows. Scroll up: new turns arrive without moving you. The turn
    list, overview counts and tab counts update. Open a dialog on a tool of an earlier
    turn: it stays on that item while turns arrive.
18. In devtools' Elements panel, an earlier turn's `<article>` is not re-created when a new
    turn arrives (it keeps any toggle you opened, such as "+1 reminder").

### Keys and themes (AC13, AC14)
19. Every action is a real button or link: reach each with Tab, run it with Enter. `j`/`k`
    step through turns unless focus is in a text field.
20. The theme defaults to dark; pick light in the header, reload: light is kept. Every
    status reads as glyph and word, never colour alone.
21. Contrast, in **both** themes:
    - Lighthouse (devtools → Lighthouse → Accessibility, desktop): no "Background and
      foreground colors do not have a sufficient contrast ratio" items. Record the score.
    - Paste this in the console and record the minimum and any line it prints:

      ```js
      (() => {
        const rgb = (c) => (c.match(/[\d.]+/g) || []).map(Number);
        const lum = ([r, g, b]) => [r, g, b].map((v) => { v /= 255; return v <= 0.03928 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4; })
          .reduce((a, v, i) => a + v * [0.2126, 0.7152, 0.0722][i], 0);
        const bg = (el) => { for (; el; el = el.parentElement) { const c = rgb(getComputedStyle(el).backgroundColor); if (c.length === 3 || c[3] > 0) return c.slice(0, 3); } return [255, 255, 255]; };
        let min = 99, bad = [];
        for (const el of document.querySelectorAll("body *")) {
          if (![...el.childNodes].some((n) => n.nodeType === 3 && n.textContent.trim())) continue;
          const s = getComputedStyle(el);
          if (s.visibility === "hidden" || s.display === "none" || !el.getClientRects().length) continue;
          const a = lum(rgb(s.color)), b = lum(bg(el));
          const r = (Math.max(a, b) + 0.05) / (Math.min(a, b) + 0.05);
          min = Math.min(min, r);
          if (r < 4.5) bad.push([r.toFixed(2), el.tagName, el.className, el.textContent.trim().slice(0, 40)]);
        }
        console.log("min contrast", min.toFixed(2)); console.table(bad);
      })();
      ```

      Run it with a dialog open too. Every pair must be ≥ 4.5:1.

### CLI (AC15)
22. Run the printed `bin/gateway timeline -config <cfg> <session>`: one block per turn with
    prompt, durations, step lines, tool lines and labelled effects, the between block, side
    calls on one line, matching the page. `-json` prints the same object as
    `curl -s http://127.0.0.1:17199/api/sessions/<id>/view` (compare with `jq -S`).

### Render budget
23. Restart the throwaway gateway with `GATEWAY_CAPTURE_DIR=/tmp/fx016-2000`, seed 2,000 calls
    (`node docs/manual-checks/seed-calls.mjs --gateway http://127.0.0.1:17197 --ui
    http://127.0.0.1:17199 --stub-port 17196`; see 013-web-ui.md for its 504 caveat), open
    that session with devtools' Performance panel recording: from navigation to the
    last turn drawn is ≤ 2 s. Record the figure.

Stop the throwaway gateway and remove `/tmp/fx016-data` and `/tmp/fx016-2000` when done.
