# CR-001 — Real-session fixture test also covers missing system content

## Request
T006: TestBuild_RealSessionFixture must also assert that the timeline builds and renders when the system content (system_hash in request events) is absent from the store, per research.md D12.

## Why
New information from the T004 privacy review (research.md D11, D12): the main thread's system prompt held the home path, so it was left out of `content.jsonl`. The six request events still carry `system_hash`, which now points at content that is not in the fixture. D12 already says TestBuild_RealSessionFixture must check the timeline survives this, but T006 in the approved tasks.md does not list it, and D12 itself says binding it needs a `/al-change`. The check is worth having: the timeline must not fail when referenced content is missing (a blob can be absent in any real store).

One wrinkle: `Build` is T006, but the text and JSON renderers are T007 (which depends on T006). T006 cannot assert rendering because no renderer exists yet. So the "builds" half goes in T006 and the "renders" half goes in T007, using the same fixture.
