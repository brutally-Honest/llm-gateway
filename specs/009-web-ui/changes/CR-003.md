# CR-003 — Rename tool_use_id to tool_call_id, two-level CSP, and T005/T008 gaps

## Request
spec and tasks:
1. AC18 and AC40: rename the tool-call field tool_use_id to tool_call_id (the canonical name already used by store and timeline as ToolCallID). Reason: tool_use_id is an Anthropic wire name banned by TestCore_NoProviderOrClientIdentifiers (AC12, D10); the purity test stays strict.
2. AC33: every response carries the required security headers; body responses (the exchange body endpoint) carry a stricter CSP, default-src 'none'; sandbox, so stored HTML bodies can never run. Add a test that the body endpoint sends the stricter CSP and every other response sends the standard one.
3. T008: add a test that Hub.Publish returns immediately when the hub's own queue is full (the overflow path that closes all streams), covering AC28.
4. New rework task after T007, renaming tool_use_id to tool_call_id in internal/ui and its tests; T013 wording uses tool_call_id.
5. New rework task for T005 code (no spec change): accept every Host form D8/AC31 allows for the configured listener (including [::1]:port where applicable), and restrict static files to GET as D4 requires (other methods 405). Add tests for both.

## Why
- Defect (items 1, 4): `tool_use_id` is a provider wire name. T007 (fadc615) emits it as a JSON tag at `internal/ui/entries.go:60`, so `TestCore_NoProviderOrClientIdentifiers` is red at HEAD (the UI package is scanned with the full list, `internal/core/purity_test.go:54`, AC12/D10). The canonical name is `ToolCallID`, already used by store and timeline. The purity test is not weakened; the spec text (AC18, AC40) and the API field change instead. Same kind of rename as CR-001.
- Decision (item 2): the exchange body endpoint serves stored bodies verbatim, which may be HTML. The standard CSP (`default-src 'self'`) would let such a body, opened directly, run same-origin; body responses get `default-src 'none'; sandbox`. T007 already sends it (`internal/ui/api_exchange.go:148`), so the spec is catching up with the code, and the behaviour has no test.
- Test gap (item 3): AC28 says publish never blocks. T008's tests cover slow subscribers, not the hub's own queue being full (the overflow path that closes all streams).
- Defect (item 5): T005 (0210f5b) accepts only the bound host:port plus `localhost:port`, but AC31 and the UI origins term (with D8) also allow `127.0.0.1:<port>` and `[::1]:<port>` and the listen host; it also does not restrict non-GET outside `/api`, which D4 requires (static files GET only, other methods 405). The spec is right; the code falls short, so no spec change.
