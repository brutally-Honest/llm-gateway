# CR-002 — T007 gains an API test for unreadable reasoning

## Request
tasks T007: add test TestAPI_TimelineOmitsUnreadableReasoning (Q1, AC18, AC11): for a session whose stored reasoning block has no readable thinking text, the timeline API returns no thinking entry for it, no entry carries [reasoning] as thinking text, and the assistant message entry still matches the CLI viewer (text [reasoning]).

## Why
A decision recorded in plan.md Open questions Q1 (thinking text): if a reasoning block has no readable text, omit the `thinking` entry rather than emit the `[reasoning]` placeholder; decided: omit. T003 now pins the timeline package behaviour: for a stored reasoning block with no readable text, `Entry.Thinking` is empty and `Text` is `[reasoning]` (stats_test.go lines 78-82, commit 573707c). The API layer built in T007 maps `Entry.Thinking` to `thinking` entries (research D2) but has no test of its own for this case, so a mapping that emitted `[reasoning]` as thinking text would pass every listed T007 test. The spec already requires the behaviour (AC18: thinking only "when the stored message content holds a thinking block"; AC11: same entries and text as the CLI viewer), so only the test list changes.
