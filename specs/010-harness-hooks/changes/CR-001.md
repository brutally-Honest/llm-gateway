# CR-001 — Live-stream correctness fixes from the branch review, viewer gaps, web client tests

## Request
Fix live-stream correctness found by the focused branch review, and tidy docs.
1. Commit path (stream.go): on a commit, compare every exchange in the session against what was sent and re-send any whose hash changed, as the hook refresh already does. Drop the plan's "never for earlier ones" rule. Regression test from the reviewer's probe: a later exchange's tool_result turns an earlier call from ran-not-reported to asked+ran+reported on an open stream.
2. Hook group (hub.go, entries.js): always send the session's hook lines as a full snapshot, empty included; the client replaces the whole hook group on receipt, and an empty snapshot removes it. Regression test: the only unmatched hook line becomes matched and disappears live (E6).
3. Ties (entries.js compareEntries): on equal time, the exchange sorts before hook lines, matching the server. Regression test on an exact-time tie.
4. Receive time (handler.go): stamp the receive time in the ingest handler with the sequence number, carry both through the queue, store both as given. Regression test: concurrent posts with writes finishing out of order keep posting order with distinct times.
5. Viewers: truncated hook input shows "… N bytes omitted" (CLI and web); unknown events show their stored name ("hook unknown: <name>"); tool-card.js hides the pending badge when a harness state exists.
6. Web client tests: add Node's built-in test runner (node --test, no npm, no node_modules) for internal/ui/web/*.js, run by make verify; ADR 0013 records it (test-only runtime, like shellcheck in ADR 0011); make setup reports whether node is installed. Tests for 2 and 3 run the real entries.js.
7. Commit the reviewer's TestStream_LiveHookUpdateReplacesFirstSnapshotHookLines with fix 2.
8. E4: hook events with no session appear only as a CLI count, not as entries in the web ungrouped list; record it as a known v1 gap.
9. Docs: rename TestPurity_HooksPackageImportsNoClientAndNamesNoHarnessEvent to TestPurity_HooksPackageImportsNoClient (tasks.md:89, plan.md:186); list internal/core/purity_test.go under T007 and in Test strategy.

Revised by the requester before approval:
- Item 4: take the sequence number and the receive time together under one lock, and keep the time non-decreasing (max(now, last)). The regression test asserts that sequence order and time order agree across concurrent posts. This replaces "keep posting order with distinct times" above: concurrent posts have no defined posting order, and two deliveries may share a time.
- Item 4, tests: the handler takes an injectable clock, and two deterministic tests carry the regression instead of timing: (1) a clock that steps backwards: stored receive times never decrease as seq increases; (2) a clock that blocks the first request inside the clock call until a second request has started, returning a later time to the first request than to the second: both requests' seq order and time order agree. Under the old two-step code the second request finishes with the higher seq but the earlier time. The concurrent-posts test stays as a smoke test. Test (2) is mutation-checked by splitting the sequence number from the stamp: it must fail. The requester asked for the mutation "move the clock call outside the lock"; a probe showed that mutant still passes, because seq and max(now, last) under the lock keep the two orders in step wherever the clock is read, so it is not a defect.
- Item 2: the hook snapshot travels in its own `hooks` SSE event, because an empty list cannot name the group it belongs to.
- Item 7 belongs only to the hook snapshot task.

## Why
A focused review of the branch, with probes reproduced on the real stack, found defects in what T013 and T012 shipped, plus decisions:
- Item 1: `writeLive` only re-sends exchanges after the first committed one (plan "Hub and streams"). A later exchange's `tool_result` changes the state of an earlier call, so the open stream ends on `ran-not-reported` while a reload shows `asked+ran+reported`. The plan rule is wrong, a wrong assumption, not a code slip. This breaks AC16 and AC26 (live must equal a reload).
- Item 2: the hooks pseudo-exchange is sent only when non-empty and the client merges it, so the last unmatched hook line stays after its exchange commits (E6, AC21 live). An empty list has no entry to carry a group key, and every hook line has `exchange_id ""` on the wire, so an empty snapshot needs an event of its own: `hooks`.
- Item 3: on an exact time tie the client sorts hook lines before the exchange; the server sorts after. The live view differs from a reload (AC24).
- Item 4: the sequence number and the receive time are taken in two separate steps: `h.seq.Add(1)` in the handler (`handler.go:61`), then `time.Now()` in `Submit` (`sink.go:128`). Both run on the request's goroutine before the item is queued, so worker order plays no part; two concurrent requests can interleave between the steps, and the later sequence number can get the earlier time. Moving both into the handler would not close that gap on its own, so they are taken together under one lock. Keeping the time non-decreasing also covers the wall clock stepping back. A concurrent test alone hits this interleaving only some of the time, so an injectable clock forces it.
- Item 5: viewer gaps against AC22 to AC24: omitted-byte count dropped, unknown event name not shown, pending badge shown beside a harness state.
- Item 6: item 2 and 3 are client logic; the existing string-pin tests cannot run it. A test-only Node runtime is the smallest way to run the real `entries.js`. A new tool needs an ADR (AGENTS.md: no new dependency without an ADR).
- Item 8: decision, E4 as written ("shown in the ungrouped list") is not what T005/T011/T012 built: the ungrouped web list lists exchanges and has no hook entries. Accepted as a known v1 gap; the spec now says so.
- Item 9: the purity test name says more than it checks (it checks only that the package imports no client); `core/purity_test.go` belongs to T007's list.

## Delta

## Plan impact
update:
- Hub and streams: delete "never for earlier ones" and the "after the first committed" cut-off; on a commit compare every exchange in `All` with `sent`. A session's hook lines are always sent as a full snapshot in a `hooks` SSE event, empty included (`[]`), on the connect snapshot, the commit path and the hook refresh; the client replaces the whole hook group on receipt, and an empty snapshot removes it. The global stream sends no `hooks` event.
- Design, Handler and Sink: the handler takes seq and receive time together under one lock, keeping the time non-decreasing (max(now, last)), and passes both through the queue; the sink and `SaveHook` store both as given. The handler's clock is injectable.
- Presentation: truncated hook input carries `N bytes omitted`; unknown events show their stored name; pending badge hidden when a harness state exists; on equal time the exchange sorts before hook lines.
- Dependencies: none new in Go. Node is a test-only runtime recorded in ADR 0013 (like shellcheck, ADR 0011).
- Test strategy: Purity test renamed `TestPurity_HooksPackageImportsNoClient`; list `internal/core/purity_test.go`; Web JS rendering is checked by Node tests of the real `entries.js` plus string pins; T012 keeps its manual look. Update the Risks line "Web JS rendering is checked by string tests only".
- Test strategy, receive time: the two injected-clock tests are the regression tests, and the concurrent-posts test is a smoke test only.
- AC coverage: add the new regression tests to AC16, AC21, AC24 and AC26 rows.

The approach (separate sink, derived states, coalesced refresh) holds; this is not a re-plan.
