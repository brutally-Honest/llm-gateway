016 web UI v2 · session page mockups

Four layouts of one made-up session (~/code/shop-api, 8 turns), same data, same colours. Pick one, then write the spec. The theme choice is remembered across pages where the browser allows storage for local files.

1 · Compact list

One dense column: every call, tool and effect is one line, and any line opens its details in place, right under itself.

Closest to today's page, so the cheapest to build; the reader never leaves the timeline.

Dropped: duration strip, rail Show options. Kept: rail, key bar.

2 · Two panes

Rail, timeline and a details pane that is always open: arrow keys walk the rows, the pane follows.

Nothing ever covers the turn you are reading; best for going through a session row by row.

Dropped: rail Show options, model-call rows (calls become chips above each turn). Kept: call strip, key bar. Needs ~1100px for three columns.

3 · Spans

Time is the main axis: model lanes per thread, a bar per tool call, each effect marked where it was seen.

Answers "what was running when this file changed" by position, which is what the attribution labels guess at.

Dropped: key bar, rail Show options. Replaced: the strip, by a session overview axis with idle time hatched. One long tool squeezes the rest of its turn.

4 · Story

Each turn is a changelog entry: you asked, what ran, what changed (diffs folded in place), what Claude answered.

Reads like a review of the turn's work; the most readable, and the longest page.

Dropped: duration strip, key bar, rail Show options, model calls as rows (they become "#5 wrote for 4.8s, then, 4 in parallel:"). Details open in a modal.

Sessions list

sessions.html — in variant 1's compact style, which suits a table best. Readable titles for sessions with no prompt, labelled counts, the unassigned connection listed with its ⚙ harness label.

Shared by all four

  • Tool lines like ✓ Bash npm test · 2m 14s, ✓ Edit src/app.js +3 −1, ✓ Skill pdf, each with its run time; a failed tool says ✗ failed in words.
  • Effects under the tool call that caused them; the 015 label as glyph + word in a badge before the path, never at the end of the line. "Several running" effects sit after the parallel calls they name; harness and outside effects in their own group.
  • Turn time from prompt to final answer, split into model time and tool time. Tool time leaves out the Agent call's span, whose sub-agent calls already count as model time.
  • Session header: every number labelled, in four groups (activity, time, effects, tokens). Side calls folded behind "2 side calls", grey, the 429 explained as the probe's expected answer.
  • Thinking only in the call's details, context size only there too. Rail prompts clamped to 2–3 lines, full text on hover or focus.
  • Paths relative to the session folder, full path on hover and in details. Turn 8 is hooks-only: "no model calls captured".
  • Dark by default with a light toggle, glyph + word for every status, every control a real button or link.
